## Confirmed architectural observations

### 1. Pending-order subsystems are disabled by default
The current source declares `UseContinuationRepending=false`, `UseExhaustionPending=false`, and `UsePendingCover=false`. Therefore a test using defaults can legitimately produce zero pending orders even though pending-order functions exist in the source.

### 2. Exhaustion logic is not yet aligned with the requested reversal architecture
The existing exhaustion comments describe stop-style reversal anticipation around structure. The requested architecture is more explicit:
- Uptrend exhaustion -> SELL LIMIT near a validated extreme/pullback zone.
- Downtrend exhaustion -> BUY LIMIT near a validated extreme/pullback zone.
- Reversal confirmation / breakout continuation -> BUY STOP or SELL STOP only when a fresh structural trigger confirms the reversal.
These must be separate states, not one generic pending subsystem.

### 3. Current entry filtering is over-constraining the timing window
The supplied journal shows 41 triggers, only 16 valid signals, 15 chase-price rejections, and 14 quorum holds. The one-month report then contains only 13 completed trades. This supports investigating signal timing and filter sequencing rather than simply increasing trade frequency.

### 4. Tick handling needs a two-speed architecture
The source already has some tick-level protection paths while the normal dynamic protection is primarily evaluated on new bars. This is directionally correct, but the implementation must avoid repeatedly recalculating indicators, dashboard objects, and trade modifications on every tick.

Required split:
- FAST PATH: price/profit/risk protection only; no indicator recalculation; no dashboard redraw.
- BAR PATH: indicator reads, signal generation, pending-order decisions, dynamic TP target updates, and dashboard refresh.
- TRADE-MODIFY GATE: only call `OrderModify` when the rounded target differs by at least the broker-valid minimum and the configured modify interval has elapsed.

## v6.49 target architecture

### A. Signal state machine
`IDLE -> SETUP -> CONFIRMED -> EXECUTABLE -> MANAGED -> EXITED`

A setup must carry direction, trend age, slope, extension, ATR, structure, S/R distance, momentum quality, and confidence. The EA must not treat a raw indicator flip as an executable market order.

### B. Market entry
Market entry is allowed only when a fresh momentum/structure event is confirmed. A stale Supertrend flip must not trigger a late market entry merely because all filters eventually agree.

### C. LIMIT reversal entries
- SELL LIMIT: only after a validated uptrend exhaustion state, at a structurally justified retracement/extreme zone above current price.
- BUY LIMIT: only after a validated downtrend exhaustion state, at a structurally justified retracement/extreme zone below current price.
- No LIMIT order merely because RSI is overbought/oversold.
- Require exhaustion + structure + rejection evidence and invalidate the order if the trend resumes with fresh momentum.

### D. STOP reversal/continuation entries
- BUY STOP: above a validated reversal structure after a downtrend shows confirmed upward transition.
- SELL STOP: below a validated reversal structure after an uptrend shows confirmed downward transition.
- STOP orders must represent confirmation, not a duplicate of market entry.

### E. Dynamic TP
The initial TP is a target, not an immutable ceiling.

When a position is running and trend strength remains valid:
- extend the TP target only in the favorable direction;
- never move TP backward;
- cap extensions using fresh structure, ATR, and broker constraints;
- freeze/convert to protection when momentum quality deteriorates.

### F. Smart trailing
Trailing is profit-protection first, not a fixed candle-count follower.

Suggested stages:
1. Before meaningful profit: structural SL only.
2. Initial profit threshold: move SL to protected/near-BE zone.
3. Proven profit: lock a fraction of realized floating profit.
4. Strong trend: follow structural swing / Supertrend floor with ATR buffer.
5. Sudden reversal: fast protection path can lock profit without waiting for the next bar close.

All trailing moves are ratchets: never loosen SL.

### G. Performance / anti-freeze design
- Indicator calculations only on a new bar unless a protection calculation explicitly requires current Bid/Ask.
- Dashboard objects update at a controlled cadence, not every tick.
- No repeated `iCustom()` calls for the same symbol/timeframe/bar within one processing cycle.
- Cache indicator values and bar timestamp.
- Trade modifications are throttled and deduplicated.
- Never use a visual object update as part of the fast protection path.

3. Pending-order counters prove BUY LIMIT, SELL LIMIT, BUY STOP and SELL STOP paths independently.
