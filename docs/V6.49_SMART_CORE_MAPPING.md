# v6.49 Smart Core Mapping

This document is the integration contract between the existing v6.48 Smart Core and the isolated v6.49 execution engine.

## Source functions verified in v6.48

| v6.49 context | v6.48 source | Mapping rule |
|---|---|---|
| `direction` | `SC_STDirection(1)` | +1 / -1 / 0 |
| `freshSTFlip` | `SC_STTrigger(1)` + `SC_STTrigger(2)` | current trigger when previous trigger is 0 |
| `haDirection` | `SC_HADirection(1)` | +1 / -1 / 0 |
| `espDirection` | `SC_ESPDirection(1)` | +1 / -1 / 0 |
| `atr` | `SC_ATR()` | closed-bar ATR |
| `supportZone` | SuperSR support/room data | validated downside support, not merely a persistent line |
| `resistanceZone` | SuperSR resistance/room data | validated upside resistance, not merely a persistent line |
| `breakoutUp` | structure/breakout state | only fresh confirmed break |
| `breakoutDown` | structure/breakout state | only fresh confirmed break |
| `chase` | existing Smart Core chase/extension filters | true means no fresh market chase |
| `sideways` | existing chop/sideways filters | true means no entry route |
| `riskBlocked` | aggregate-risk / trading pause guards | true blocks every route |
| `structurePrice` | validated S/R or breakout structure | route-specific anchor |
| `invalidationPrice` | structural invalidation | used to derive risk distance |

## Existing v6.48 execution functions

The v6.48 EA already contains:

- `SC_BuildPlan()` for market/limit/stop planning.
- `SC_Execute()` for broker execution.
- `SC_ManagePending()` for pending lifecycle.
- `SmartCoreCheckEntry()` for signal gating.
- `OrderSendRetry()` for transient execution errors.
- `SafeOrderModify()` to avoid no-op broker modifications.

v6.49 must not duplicate these broker primitives. The new engine should decide **which route is appropriate**, while the host remains responsible for broker constraints and order lifecycle.

## Route policy

### MARKET
Require fresh Supertrend trigger, aligned HA/ESP/structure, minimum quorum, and no chase/sideways/risk block.

### BUY LIMIT / SELL LIMIT
Use only when the established move is exhausted and a validated support/resistance zone provides a pullback/reversal entry. Never place a LIMIT merely because price is far from the Supertrend line.

### BUY STOP / SELL STOP
Use only after reversal direction is confirmed and a fresh structure break validates the new direction. The stop is confirmation, not prediction.

## Protection policy

- SL ratchets only in the profitable direction.
- TP extends only in the profitable direction and only after new structural/momentum justification.
- No repeated `OrderModify()` when normalized SL/TP is unchanged.
- Intrabar tick processing is reserved for emergency protection; indicator panels and full signal evaluation remain bar-driven.

## Implementation gate

The isolated v6.49 host currently remains fail-closed. It must not be connected to live broker execution until the exact SuperSR/structure fields are mapped from the v6.48 indicator cache and the resulting EA compiles cleanly in MetaEditor.
